Users open a ticket from the **help button** at the bottom right of every page, **Help & support** in the sidebar, or **Settings → Help & support**. Some buttons open one already filled in, such as **Ask us to add it** in the Email log and **Report to support** in Ingestion issues.

Each ticket has a category the user picks: Question, Bug / problem, Billing, Account, Job site request or Other. A seventh, Account deletion, is created only by the deletion request flow, so users can't pick it.

To stop floods, a user can open at most 5 tickets an hour and have at most 8 open at once.

## Answering

Tickets arrive in admin **Tickets**, with counts by status and a table you can filter and act on in bulk. Each ticket has a number like **TKT-0042**, which both sides see.

Conversations are live in both directions. A reply appears in the other person's open chat without a reload, with sent, delivered and read ticks. An admin reply also creates a notification for the user, but doesn't email them.

## Statuses

| Status | Meaning |
|---|---|
| Open | Waiting for us |
| In progress | Being worked on |
| Resolved | Done. The user is emailed the full conversation, and can't reply any more; they raise a new request instead |

Admin replies and the user's messages are rich text, cleaned of anything unsafe when saved.
